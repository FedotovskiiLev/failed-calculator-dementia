# FAILED Calculator — dementia build

[English](README.md) · [**Русский**](README.ru.md)

> Калькулятор, который начинает без математики, открывает правила по мере использования, строит собственные таблицы и алгоритмы, а затем постепенно забывает выученное.

FAILED Calculator — намеренно переусложнённый браузерный эксперимент про обучение, память и вычислительный абсурд. Его задача не в том, чтобы считать как можно быстрее. Наоборот: калькулятор сначала должен приобрести математическое знание и только после этого может уверенно им пользоваться.

## Что он делает

Каждый новый браузерный сеанс начинается с пустого математического мозга. Никакого списка заранее известных операций нет: пользователь просто пишет выражение.

```text
2 + 2
7 * 8
2 + 5i
sqrt(-1)
sin(pi/2)
(2+3i)*(4-i)
12!
```

Первая встреча с неизвестным понятием специально занимает заметное время. Калькулятор реагирует на увиденное, формирует гипотезу о новой операции, строит правило и сохраняет полученное знание.

Арифметика небольших целых чисел запоминается буквально в виде таблиц. Более общие случаи обрабатываются выученными алгоритмами и отдельными эпизодическими воспоминаниями. Повтор уже хорошо знакомого примера обычно происходит быстрее первого знакомства.

А затем память начинает разрушаться.

## Постепенная деменция

Забывание происходит постепенно, а не одним полным сбросом по таймеру.

Приступ может:

- снизить уверенность в математическом понятии;
- повредить отдельные ячейки выученной таблицы;
- полностью удалить некоторые ячейки;
- ослабить или стереть эпизодические примеры;
- со временем уничтожить сам смысл операции.

Во вкладке **«Память»** этот процесс виден буквально. Здоровые ячейки остаются яркими, повреждённые тускнеют, а забытые превращаются в дырки.

Частично забытое понятие калькулятор может восстановить при новой встрече. Полностью забытая операция снова воспринимается как настоящее открытие.

**Журнал наблюдателя** и **Графики** специально находятся как бы снаружи мозга, поэтому переживают потерю памяти и показывают весь цикл обучения и распада.

## Математическая модель

Парсер не использует `eval()`, а вычислитель не сводит выражение к скрытому вызову готовых трансцендентных функций.

Проект намеренно выводит результаты через изученные методы:

| Понятие | Метод |
| --- | --- |
| Сложение | рекурсия через следующий/предыдущий элемент и явные таблицы |
| Вычитание | обратное сложение |
| Умножение | повторное сложение и выученные таблицы |
| Деление | повторное вычитание / реконструкция в духе деления столбиком |
| Остаток | повторное вычитание |
| Целая степень | повторное умножение |
| Факториал | повторное умножение |
| Квадратный корень | метод Ньютона |
| `exp` | ряд Тейлора |
| `sin`, `cos` | ряды Тейлора |
| `tan` | выученные синус/косинус и деление |
| `ln` | логарифмический ряд |
| `pi` | приближение рядом Нилаканты |
| `e` | сумма обратных факториалов |
| Комплексная арифметика | разложение на уже изученные операции над действительными частями |

Числа JavaScript всё равно остаются самым нижним физическим слоем браузера. Важное отличие архитектуры в другом: у вычислителя нет скрытого пути «просто мгновенно посчитать запрошенное выражение». Новое поведение проходит через явное обучение, сохранённые знания и видимые алгоритмы вывода.

## Поддерживаемый синтаксис

```text
+  -  *  /  %  ^  !
( )

2i
2pi
2(3+4)

pi
e
i

sqrt(x)
abs(x)
sin(x)
cos(x)
tan(x)
ln(x)
log(x)
exp(x)
```

Комплексные числа являются нормальным вводом. `2+5i` не считается ошибкой синтаксиса: калькулятор должен открыть мнимую единицу и расширить собственное представление о числах.

Модель намеренно конечна. Некоторые области — например общий комплексный логарифм или произвольные нецелые комплексные степени — пока находятся за границей её математического знания и не передаются молча готовому math-движку.

## Русский и английский интерфейс

Весь сайт работает на русском и английском. Переключатель языка меняет не только подписи интерфейса, но и внутренний монолог, сообщения памяти, деменции и журнал наблюдателя.

Выбранный язык хранится в `localStorage`. Сама математическая память остаётся привязанной к текущему браузерному сеансу.

## Модель состояния

Мозг калькулятора живёт в `sessionStorage`.

Это даёт именно нужное поведение:

- новый посетитель начинает с полностью пустого мозга;
- обновление страницы в той же вкладке сохраняет текущий мозг;
- разные посетители не делятся математическими воспоминаниями;
- завершение браузерного сеанса уничтожает конкретную личность калькулятора;
- журнал и статистика остаются локальными и никуда не отправляются.

Backend, аккаунтов, аналитического сервиса и сетевого API нет.

## Графики

Раздел **«Графики»** записывает когнитивную историю калькулятора:

- целостность памяти;
- количество сохранённых знаний;
- число известных понятий;
- накопленное число приступов деменции.

Графики рисуются напрямую в `<canvas>` без сторонней библиотеки.

## Локальная разработка

Подойдёт любой сервер статических файлов. Например:

```bash
python -m http.server 8000
```

После этого открой `http://localhost:8000`.

Быстрая проверка синтаксиса JavaScript:

```bash
node --check app.js
```

## Принципы проекта

1. **Обучение должно быть видно.** Новая математика должна занимать заметное время и сопровождаться внутренним монологом.
2. **Память должна быть наблюдаемой.** Таблицы и повреждённые ячейки являются частью интерфейса, а не скрытой реализацией.
3. **Забывание должно иметь последствия.** Деменция меняет будущие вычисления, а не просто двигает индикатор.
4. **Комплексные числа не являются «ошибкой ввода».** Странная, но поддерживаемая математика должна вызывать открытие.
5. **Никакого скрытого мгновенного калькулятора.** Вычислитель должен предпочитать таблицы, вывод и явные численные методы.
6. **Шутка должна оставаться технически интересной.** Абсурд работает лучше, когда под ним находится настоящая система.

## Защита от зависаний

FAILED Calculator намеренно неэффективен, но это не означает, что ему разрешено бесконечно замораживать вкладку.

Каждое выражение выполняется внутри ограниченного бюджета вычислительной работы. Долгие пошаговые алгоритмы регулярно сохраняют последнее осмысленное промежуточное состояние. Если следующий этап потребует слишком много плотных циклов и начнёт превращаться в реальный жор CPU, калькулятор прекращает текущую мысль, сохраняет всё уже выученное и показывает лучшее приближение или промежуточный результат, до которого успел дойти.

Например, при самостоятельном выводе `e` через сумму обратных факториалов примитивный алгоритм умножения в какой-то момент может стать слишком дорогим. Тогда интерфейс покажет последнее полученное приближение `e`, а не незаметно подставит `Math.E` и не оставит вкладку зависшей.

Защитный лимит **не является** запасным обычным калькулятором: незавершённое вычисление никогда не заменяется скрытым готовым ответом.

## Известные ограничения

- Это художественно-образовательная модель математического обучения, а не CAS.
- Для приближённых действительных вычислений остаются ограничения floating point JavaScript.
- Символьная алгебра общего вида не реализована.
- Общий комплексный логарифм и произвольные комплексные степени пока намеренно неполны.
- Размер таблиц ограничен, чтобы не убить браузер; большие случаи становятся алгоритмическими или эпизодическими знаниями.
- Механика деменции является вымышленным поведением программы и не претендует на медицинскую модель человеческой деменции.

## Участие в разработке

Issues и pull requests приветствуются. Особенно полезны новые способы математического вывода, более интересная деградация памяти, дополнительные математические понятия, улучшения доступности, тесты парсера и новые способы визуализации знаний.

При добавлении математической возможности лучше строить явный процесс открытия и вывода, а не заменять его прямым вызовом готовой функции.
